# Project Charter
## Mac Computer Diagnostics and IT Support Lab

**Project ID:** APLUS-LAB-001  
**Version:** 1.0  
**Status:** Planning  
**Project owner:** Project developer  
**Start date:** October 27, 2026  
**Target completion:** Within one week, depending on progress  
**Budget:** $0  
**Primary tools:** macOS built-in utilities and Terminal

## 1. Project Purpose

The purpose of this project is to develop and demonstrate practical entry-level IT support skills through a structured computer diagnostics investigation.

The project will use a MacBook Pro running macOS as the test device. The investigation will collect relevant system information, inspect storage usage, review memory and system details, and document findings in a professional technical report.

The project is designed to reinforce CompTIA A+ knowledge while producing evidence of practical troubleshooting, command-line use, technical analysis, and documentation skills.

## 2. Problem Statement

IT support technicians need to identify computer specifications, collect reliable diagnostic information, recognize potential issues, and document their findings before recommending corrective actions.

This project will practice that process using built-in macOS tools and a controlled, non-destructive diagnostic procedure.

## 3. Project Objectives

1. Identify the computer's model, processor, installed memory, and operating system.
2. Inspect storage capacity and available disk space.
3. Collect relevant system information using command-line tools.
4. Interpret diagnostic output and distinguish observations from assumptions.
5. Record the tests performed, commands used, and results obtained.
6. Identify any issues that warrant further investigation.
7. Produce a final technical report with evidence and recommendations.
8. Prepare a sanitized project summary suitable for a résumé and LinkedIn portfolio.

## 4. Scope

### Included

- Hardware and system identification.
- Operating system identification.
- Storage capacity and free-space checks.
- Memory and relevant system information.
- Basic, non-destructive diagnostic commands.
- Diagnostic logs, screenshots, and technical documentation.
- Final report and portfolio preparation.

### Excluded

- Opening the computer or replacing hardware.
- Deliberately damaging or stressing the system.
- Deleting files or changing important system settings.
- Installing paid diagnostic software.
- Claiming hardware failure without sufficient evidence.
- Performing advanced repairs outside the project's scope.

## 5. Tools and Resources

- MacBook Pro with Apple silicon.
- macOS System Information.
- Terminal.
- Built-in commands such as `system_profiler`, `df`, and other appropriate read-only diagnostic utilities.
- A text editor for documentation.
- Free tools for preparing portfolio evidence.

## 6. Deliverables

The project will produce:

1. Project charter.
2. Project plan and task checklist.
3. Diagnostic log.
4. Evidence screenshots, with sensitive details removed.
5. Final technical report.
6. LinkedIn-ready project summary.

## 7. Success Criteria

The project will be considered complete when:

- Required system information has been collected.
- Planned diagnostic checks have been performed.
- Results have been recorded accurately.
- Conclusions are supported by evidence.
- Any limitations or unresolved questions are documented.
- The final report is complete and understandable.
- Public evidence has been reviewed for privacy and security.

## 8. Risks and Controls

**Risk:** Sensitive device information is exposed publicly.  
**Control:** Remove serial numbers, hardware UUIDs, usernames, and other identifying details from public evidence.

**Risk:** A normal diagnostic result is incorrectly described as a failure.  
**Control:** Record observations separately from conclusions and recommendations.

**Risk:** A command unintentionally changes system settings or data.  
**Control:** Prefer read-only commands and review unfamiliar commands before running them.

**Risk:** The project is presented as professional work experience.  
**Control:** Clearly label it as an independent hands-on lab project.

## 9. Project Method

The project will follow these stages:

1. Plan the investigation.
2. Identify the device and environment.
3. Perform diagnostic checks.
4. Record results and evidence.
5. Interpret findings.
6. Prepare recommendations.
7. Complete the technical report.
8. Prepare the portfolio summary.

Each stage will be reviewed before proceeding to the next.

## 10. Final Outcome

The expected outcome is a documented, hands-on computer diagnostics project that demonstrates practical IT support skills relevant to entry-level technical support roles.

The project will also provide a foundation for future labs involving networking, operating system troubleshooting, security, and the development of AMK TechPilot AI.
